    Plugin (Node Type) Development Guide

    Learn how to create custom workflow nodes for AYON Workflow with best practices.

    AYON Workflow supports two approaches for defining custom nodes: 1. Class-based Approach (OOP): Groups properties, execution logic, and revert logic into a single class. 2. Dictionary-based Approach: Defines nodes using dictionaries and separate functions.

    Addon structure

    The workflow addon uses a plugin discovery system that automatically finds and registers plugins from all installed AYON addons. Each plugin then becomes available as a node type when building a graph.

    # Discover all available node definitions
from ayon_workflow.plugin_system import register_all_plugins
register_all_plugins()

    [!NOTE]
    Currently all vanilla plugins are implemented within ayon-workflow but this will change in the future.

    Ensure your addon defines the following structure:

    ayon_your_addon/
├── plugins/
│   └── workflow/
│       ├── __init__.py          # get_plugins() for plugin registration

    [!NOTE] Custom Plugin Locations

    Plugins outside of official AYON addons can be discovered by setting the AYON_WORKFLOW_ADDITIONAL_PLUGIN_PATH environment variable.

    Any Python package or module placed in these paths that exposes a get_plugins() function will be loaded.

    text C:\my_plugins\ <-- The path set in the env variable └── my_custom_nodes.py <-- Exposes get_plugins()

    ```bash

    Linux/macOS

    export AYON_WORKFLOW_ADDITIONAL_PLUGIN_PATH=/path/to/my_plugins

    Windows

    set AYON_WORKFLOW_ADDITIONAL_PLUGIN_PATH=C:\my_plugins ```

    Creating Simple Nodes

    Here is how to create a simple node that converts text to uppercase.

    1. Class-based implementation

    File: plugins/workflow/__init__.py

    """Workflow plugins for your addon."""
from typing import List, Type

from ayon_workflow.plugin_system.interface import (
    InputAttribute,
    OutputAttribute,
    WorkflowTaskNode,
)


class TextUppercase(WorkflowTaskNode):
    """Brief description of functionality."""

    # Semantic version of the node (required, must have at least 3 parts e.g. "1.0.0")
    version = "1.0.0"

    # Define the inputs of the node
    inputs = [
        InputAttribute(
            name="input_text",
            description="Input text to process",
            widget={}  # Optional UI widget paramters
        )
    ]

    # Define the outputs of the node
    outputs = [
        OutputAttribute(
            name="result",
            "description": "Processed output"
        )
    ]

    def execute(self, input_text: str = "default_value") -> str:
        """Define the execution logic of the node.

        Type hints and default values in this method's signature are automatically 
        parsed to generate the node's API description.
        """
        return input_text.upper()


def get_plugins() -> List[Type[WorkflowTaskNode]]:
    """Return list of plugin classes to register."""
    return [TextUppercase]

    2. Dictionary-based implementation (legacy)

    File: plugins/workflow/__init__.py

    """Workflow plugins for your addon."""
from typing import List, Dict


def get_plugins() -> List[Dict]:
    """Return list of plugin descriptions."""
    return [
        {
            "name": "TextUppercase",  # plugin name
            "description": "Brief description of functionality",  # plugin description
            "version": "1.0.0",  # backward-compatibility support
            "inputs": [
                {
                    "name": "input_text",  # input name
                    "type": str,  # input type, annotations are supported
                    "default": "default_value",  # input default value
                    "description": "Input text to process",  # input description
                    "widget": {}  # Optional UI widget parameters
                }
            ],
            "outputs": [
                {
                    "name": "result",  # output name
                    "type": str,  # output type
                    "description": "Processed output",  # output description
                }
            ]
        }
    ]


def get_plugin_function(plugin_name: str) -> object:
    """Retrieve the actual function for a plugin."""
    if plugin_name == "TextUppercase":
        return my_custom_func
    raise ValueError(f"Unknown plugin: {plugin_name}")


def my_custom_func(input_text: str) -> str:
    return input_text.upper()

    Testing your nodes

    from ayon_workflow.workflow_editor.workflow import Workflow
from ayon_workflow.workflow_execution import execute_in_memory
from ayon_workflow.plugin_system import register_all_plugins

# Discover all available node definitions
register_all_plugins()

# Create a workflow
workflow = Workflow(name="test_workflow")

# Add your custom node
graph = workflow.execution_graph
node = graph.create_node("TextUppercase", label="my node")
node["input_text"] = "hello world"

# Execute the workflow
result = execute_in_memory.execute_workflow(workflow)

    Creating Complex Nodes

    Multiple Inputs, Multiple Outputs

    When a node returns multiple outputs, the execute function must return a tuple. The type annotations must accurately reflect this structure.

    from ayon_workflow.plugin_system.interface import (
    WorkflowTaskNode,
    InputAttribute,
    OutputAttribute,
)

class ConcatenateAndFloat(WorkflowTaskNode):
    """Join multiple strings + Float."""

    version = "1.0.0"

    inputs = [
        InputAttribute(
            name="text1",
            description="First text",
        ),
        InputAttribute(
            name="text2",
            description="Second text",
        ),
        InputAttribute(
            name="separator",
            description="Separator between texts",
            default=" ",
        ),
    ]

    outputs = [
        OutputAttribute(
            name="concatenated_text",
            description="Concatenated text",
        ),
        OutputAttribute(
            name="float_value",
            description="Unecessary float value.",
        ),
    ]

    def execute(
        self,
        text1: str,
        text2: str,
        separator: str = " "
    ) -> tuple[str, float]:
        """Join texts and return a float.

        IMPORTANT: When returning a tuple, the output order in the tuple 
        must match the order in the `outputs` dictionary.
        """
        return f"{text1}{separator}{text2}", 1.0

    Revert Functions

    Revert functions provide cleanup/undo operations for nodes that perform side effects (file creation, API calls, etc.). Any arbitrary logic can be defined as revert function.

    Class-based

    In the class-based approach, simply override the revert_execute method. It receives the same parameters as the execute method.

    import os
from ayon_workflow.plugin_system.interface import (
    WorkflowTaskNode,
    InputAttribute,
    OutputAttribute,
)


class CreateFile(WorkflowTaskNode):
    """Create a file."""

    version = "1.0.0"

    inputs = [
        InputAttribute(
            name="file_path",
            description="Path to create",
            widget={"type": "filepath"},
        ),
        InputAttribute(
            name="content",
            description="File content",
            default="random_content",
        ),
    ]

    outputs = [
        OutputAttribute(
            name="created_path",
            description="Path of created file",
        ),
    ]

    def execute(self, file_path: str = "", content: str = "random_content") -> str:
        with open(file_path, 'w') as f:
            f.write(content)
        return file_path

    def revert_execute(self, file_path: str = "", content: str = "random_content"):
        if os.path.exists(file_path):
            os.remove(file_path)

    Using AYON Datatypes

    The workflow addon provides several datatype classes in ayon_workflow.datatypes. You can use these types in your execute type hints.

    • ContextItem: Base class for AYON context items
    • ProjectItem: Represents a project
    • FolderItem: Represents a folder/asset
    • TaskItem: Represents a task
    • FrameRange: Frame range with first_frame, last_frame
    • ImageSequence: Image sequence with directory, head, tail, padding
    • Video: Video file with path and frame_range

    Use these types for better integration with AYON's ecosystem.

    Multiple platform support for resources files

    It might be handy for your node to support input coming from multiple platform, multiple mounts. The recommended approach is to store rootless paths in your workflow, than delegate the mount based resolve at execution runtime.

    import os

from ayon_workflow.plugin_system.interface import (
    WorkflowTaskNode,
    InputAttribute,
    OutputAttribute,
)
from ayon_workflow.utils import remap_input

class CreateRootlessFile(WorkflowTaskNode):
    """Create a file with content, handling rootless inputs.

    Input file_path can either be:
    * /path/to/an/explicit/file.ext (explicit)
    * {root[work]}/to/a/file.ext (rootless)
    """

    version = "1.0.0"

    inputs = [
        InputAttribute(
            name="context",
            description="Context item",
        ),
        InputAttribute(
            name="file_path",
            description="Path to create",
            widget={"type": "filepath"},
        ),
        InputAttribute(
            name="content",
            description="File content",
            default="default_content",
        ),
    ]

    outputs = [
        OutputAttribute(
            name="created_path",
            "description": "Path of the created file"
        ),
    ]

    def execute(self,
            context: ContextItem,
            file_path: str,
            content: str = "default_content"
        ) -> str:
        # Remap to correct mount if a rootless file path is provided as input.
        remapped_path = remap_input(file_path, context.project_name)

        # Create the file on current OS.
        with open(remapped_path, 'w') as f:
            f.write(content)

        # Return original rootless path to next node,
        # as we don't know which platform will run it next.
        return file_path

    def revert_execute(self,
            context: ContextItem,
            file_path: str,
            content: str = ""
        ):
        """Delete the created file (rootless)."""
        # The revert function receives the same inputs as the original function.
        remapped_path = remap_input(file_path, context.project_name)

        # Delete the file on current OS.
        if os.path.exists(remapped_path):
            os.remove(remapped_path)

    Best Practices

    1. Version Format: The version attribute must be defined and follow standard formats (e.g. 1.0.0).
    2. Execution Signature: (Class-based) The parameter names in your execute function must strictly match the keys declared in your inputs dictionary.
    3. Type Hints: Always use type hints in your execute signature (def execute(self, text: str) -> str:). The framework parses these to determine the types of your UI widgets and outputs.
    4. Default Values: (Class-based) Default values should be placed directly in the execute method signature (e.g., def execute(self, text: str = "Default"):).
    5. Docstrings: The docstring of the class (or description field in dict-based) automatically becomes the description of the Node in the editor UI.
    6. Error Handling: Fail early with descriptive error messages.
    7. Cross-Platform Compatibility: Always use remap_input() when your node accepts file paths. Production environments often mix Linux render nodes with Windows/macOS workstations.
